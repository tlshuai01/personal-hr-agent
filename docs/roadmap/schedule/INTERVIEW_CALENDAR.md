# 面试日程管理（规划）

> 状态：**待做**（小型独立应用 → 再接入个人求职 Agent）  
> 更新：2026-09-01

## 目标

做一个**日程记录型小型应用**，管理面试预约（时间、公司、岗位、渠道、备注、结果）。  
后续由 **个人求职 Agent** 介入：从 Boss / 分享对话里识别「约面试」意图，读写日程，并在回复中引用已有安排（防撞期、提醒准备）。

## 分阶段

### S0 — 独立小应用（先做）

- 本地可跑的面试日程 CRUD（日期时间、公司、职位、来源渠道、状态：待定/已约/完成/取消）
- 简单列表 + 日历或按日视图即可，不做复杂协作
- 数据默认本地（SQLite / JSON），不上传
- 可选：到期提醒（系统通知或邮件，非必须）

### S1 — 与 Agent 打通

- Core 提供对内 API：`list / create / update` 面试事件（鉴权同 Bridge secret）
- Channel / 对话侧：识别「明天下午三点面试」「改到周五」类意图 → 调日程 API
- 回复策略：已有冲突时主动说明；无冲突可确认写入
- 知识库不写死具体预约（预约是运行时状态，进日程库，不进 Markdown 事实源）

### S2 — 增强（可选）

- Boss 消息时间线 ↔ 日程双向关联（sessionId）
- 面试前自动生成「该公司/岗位」复习要点（RAG 摘要）
- 多渠道统一日历视图

## 边界

| 做 | 不做（初期） |
|----|--------------|
| 个人面试预约管理 | 多人共享日历 / SaaS |
| 本地优先、可备份 | 强制云同步 |
| Agent 读写日程 API | Agent 自动代发日历邀请给 HR（需另议） |

## 建议落地位置

- 独立目录或小仓：`interview-schedule/`（或 `apps/schedule/`）
- 仅通过 HTTP 调个人求职 Agent；Agent 不直连日程 DB 以外的渠道存储

## 验收（S0）

- [ ] 能增删改查一条面试预约
- [ ] 按时间列出「今天 / 本周」
- [ ] README 写清数据文件路径与备份方式

## 验收（S1）

- [ ] `POST /api/internal/schedule`（或等价）可创建事件
- [ ] dry-run 对话能说出「已记入周三 14:00 面试」且落库
- [ ] 冲突检测至少一种（同时间段重叠）
